# Как разместить NEXORA на своём хостинге

## Вариант 1. Обычный хостинг с файловым менеджером

1. Распакуйте архив проекта на компьютере.
2. Откройте папку `dist`.
3. Загрузите **все файлы и папки из неё** в корневую папку сайта на хостинге.
   Она может называться `public_html`, `www` или иначе — название видно
   в панели вашего хостинга.
4. В корне сайта должен лежать `index.html`, а рядом — папки `avr`, `art`
   и другие файлы. Не загружайте один `index.html` отдельно.
5. Откройте адрес сайта. Если размещаете в подпапке, используйте адрес с
   завершающим слешем, например `https://ваш-домен.ru/nexora/`.

Для такой публикации не нужны база данных, PHP, Node.js на сервере,
ключи API или привязка к ChatGPT. Компилятор работает в браузере.

## Вариант 2. Хостинг предлагает сборку из исходников

- Команда установки: `npm ci`.
- Команда сборки: `npm run build`.
- Папка публикации: `dist`.
- Переменные окружения для работы приложения не требуются.

Папка `dist` уже собрана: если хостинг принимает готовые статические файлы,
пересборку можно пропустить.

## Проверить проект у себя до загрузки

Установленный Node.js позволяет запустить готовую сборку без `npm ci`:

```sh
npm start
```

Затем откройте `http://127.0.0.1:8080`. Не открывайте HTML через `file://`:
модульный JavaScript и компилятор в Worker требуют HTTP(S).

Если порт занят, закройте предыдущий сервер. Другой порт в PowerShell:

```powershell
$env:PORT = "8090"
npm start
```

Для Node-хостинга со своим веб-прокси можно запускать `npm start`, задав
`NEXORA_HOST=0.0.0.0` и `PORT` согласно настройкам этого хостинга.
Для обычного статического хостинга этот вариант не нужен.

## Если верстак открылся, но программа не компилируется

1. Проверьте, что папка `avr` загружена целиком. В ней находятся Worker,
   WebAssembly-компилятор и файлы Arduino; часть из них довольно большая.
2. Сервер должен отдавать `.js` как JavaScript, `.json` как JSON,
   `.wasm` как `application/wasm`, `.webp` как `image/webp`.
3. Запросы к файлам `avr/...` должны возвращать сами файлы.
   Не перенаправляйте все запросы без разбора на `index.html`.
4. Если на хостинге задана строгая Content Security Policy, разрешите
   модульные Worker и выполнение WebAssembly с того же источника.

Первая компиляция загружает локальные инструменты и может идти дольше
следующих. Это отдельная загрузка, не связанная с сюжетными картинками.

## Что будет с сохранениями

Прогресс хранится локально в браузере для конкретного адреса сайта.
На другом домене, в другом браузере или после очистки данных он не переносится.
У каждого учащегося на своём устройстве будет своё прохождение.

## Что редактировать

Сюжет — `game.js`, уроки — `lessons.js`, оформление — `dist/style.css`,
разметку — `dist/index.html`. После правок JavaScript выполните
`npm run build` и загрузите обновлённое содержимое `dist`.

Сохраняйте `package-lock.json`: он фиксирует версии зависимостей для пересборки.
Папку `node_modules` в архив и на статический хостинг загружать не нужно.
