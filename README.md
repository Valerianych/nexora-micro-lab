# NEXORA — учебный веб-квест

Полный проект: исходники и файлы сайта в папке `dist`. Перед первым запуском
клонированного репозитория выполните `npm ci && npm run build`: сборка также
копирует локальный компилятор Arduino, бинарные файлы которого не хранятся в git.
Инструкция по размещению: **HOSTING.md**.

## Быстро разместить сайт

Загрузите **содержимое** папки `dist` в папку сайта на хостинге. Рядом с
`index.html` должны остаться `app.js`, `game.js`, `style.css`, папки `art`,
`avr`, `licenses` и остальные файлы. Серверная база данных и Node.js
для готовой сборки не нужны. Открывайте сайт по HTTP(S), а не двойным
щелчком по `index.html`.

### GitHub Pages

В репозитории уже есть workflow `.github/workflows/pages.yml`. После первого
push откройте **Settings → Pages**, в пункте **Source** выберите
**GitHub Actions**. Следующие обновления ветки `main` будут публиковаться
автоматически.

### Vercel

Конфигурация находится в `vercel.json`. При импорте репозитория Vercel сам
выполнит `npm run build` и опубликует папку `dist`.

## Что реализовано

- Дело 001 «Маяк замолчал»: цепь, переменные, типы данных, условие по кнопке.
- Дело 002 «Сирена сбилась»: осмотр неисправности, измерение импульсов,
  пошаговое объяснение `for`, ремонт и проверка сигнала.
- Дело 003 «Пульт забыл команды»: массив `durations` и индексы.
- Дело 004 «Одинаковые команды»: функции и параметры `blink`.
- Дело 005 «Серверная перегревается»: аналоговый датчик TMP36, `analogRead`
  и порог `>= 35 °C`.
- Дело 006 «Аварийный протокол»: датчик, кнопка, логическое `||`, массив,
  цикл и функция в одной проверяемой программе.
- Дело 007 «Самостоятельная смена»: пустая схема Arduino и пустые `setup/loop`,
  собственные имена в коде, сборка сигнальной станции без подсказок. Приёмка
  проверяет температурный порог, кнопку, ритм и возврат к норме.
- После аттестации — пропуск сотрудника и вторая арка отдела полевых систем.
- Дело 008 «Первый рабочий пропуск»: ESP32, GPIO, 3,3 В, индикатор по кнопке.
- Дело 009 «Энергии должно хватить»: АЦП, делитель напряжения, LEDC и защита батареи.
- Дело 010 «Горизонт под контролем»: два датчика I²C, расстояние и наклон, границы условий.
- Дело 011 «Три взгляда на участок»: SPI-камера, сервопривод, массив направлений,
  выдержка и одно срабатывание на новое нажатие кнопки.
- Дело 012 «Разведка насосной станции»: самостоятельная сборка всех модулей ESP32,
  разрешение запуска, три отдельных снимка и прерывание при изменении условий.
- Комикс со сценами действий, персонажами, уликами и отчётами.
- Редактор Arduino C++, подсказки и диагностика ошибок.
- Единые обозначения контактов в инструкции и на деталях; нажатие на название
  в инструкции подсвечивает нужный контакт. Детали перемещаются по всему полю,
  расположение сохраняется; «Разложить детали» сохраняет программу и провода.
- Локальная компиляция в WebAssembly и выполнение на эмуляторе ATmega328P.
  Провода влияют на результат; проверяется реальный сигнал.
- Автосохранение этапа, навыков, журнала, кода, проводов и температуры датчика
  в текущем браузере; в архиве можно повторить отдельное дело или очистить
  весь прогресс.
- Облегчённые WebP-иллюстрации, предзагрузка соседних сцен, одновременное
  появление готового кадра и текста, повтор загрузки при сетевой ошибке.

## Запуск на компьютере

Если установлен Node.js, откройте терминал в корне проекта:

```sh
npm ci
npm run build
npm start
```

Откройте `http://127.0.0.1:8080`. После сборки сервер отдаёт готовые статические файлы. Остановить сервер: `Ctrl+C`.

```sh
npm ci
npm run build
```

После пересборки загружайте обновлённую папку `dist` на хостинг.

Тесты логики: `npm run check`. Проверка компилятора, схем и учебных программ:
`node verify.mjs` после установки зависимостей и сборки.

Проверка дел 003–006 в настоящем браузере:

```sh
npx playwright install chromium
npm run build
npm run check:browser
```

Тест начинает с сохранения после дела 002. Далее он нажимает кнопки разбора,
соединяет контакты, компилирует исходные и исправленные программы, проверяет
отклонение ошибок, закрытие дел и переходы между ними. Также проверяются
удаление проводов на схеме, контраст текста, сохранение и оба варианта сброса.
В конце проверяются мобильная ширина и удаление с клавиатуры.
`NEXORA_BROWSER_PATH` позволяет указать установленный Chromium;
`NEXORA_TEST_ARTIFACTS` — каталог снимков (по умолчанию `/tmp/nexora-browser-check`).

`npm run check:workspace` проверяет совпадение названий в инструкции и на схеме,
сборку всех восьми соединений финального дела, подсветку контактов, перетаскивание
к краям поля, сохранение расположения и адаптацию при изменении ширины окна.

## Проверка новой арки

`npm run check:career` — программы и ошибочные варианты для всех пяти дел ESP32.
`npm run check:career-browser` — дело 007 с настоящим AVR GCC, затем 008–012:
провода через интерфейс, исполнение в Worker, снимки, переходы, сохранение и сброс.
Тестовые решения лежат в `verify-career.mjs`; они не входят в публикацию `dist`.

## Границы текущей версии

12 законченных дел: 7 в арке Arduino и 5 в арке ESP32. Самостоятельные дела 007
и 012 начинаются без схемы и решения; подсказки и автодополнение отключены.
Проверка сообщает нарушенное требование. Прогресс старых дел сохраняется.

Arduino: реальная компиляция AVR GCC и эмуляция ATmega328P через AVR8js.
ESP32: интерпретатор учебного подмножества Arduino C++ (JSCPP), который исполняет
код в отдельном Worker. **Это не эмуляция Xtensa/RISC-V, не ESP-IDF и не сборка
прошивки для настоящей платы.** Поддерживаются переменные, условия, циклы,
массивы, функции, GPIO, АЦП, `delay`, `millis`, Serial и модели модулей стенда.
Произвольные библиотеки ESP32, Wi-Fi, Bluetooth, RTOS и физика полёта не реализованы.

`NexoraModules.h` предоставляет учебные `readTilt`, `readDistance`, `servoWrite`,
`cameraBegin`, `cameraCapture`. Эти функции не существуют в стандартном Arduino
Core: экспортированный `.ino` требует замены драйверов при переносе на оборудование.
Модель камеры возвращает подготовленный снимок направления, а не видео/FPV.
Привод представляет готовую систему тяги и стабилизации; учащийся программирует
разрешение движения и фотосъёмку, а не полётный контроллер.

Параметры стенда: логика 3,3 В; GPIO34 — вход без внутренней подтяжки; АЦП
GPIO32/33/34 0–4095 с модельным диапазоном 0–3,3 В; LEDC использует API
`ledcAttach(pin, freq, bits)` и `ledcWrite(pin, duty)`. Аналоговая нелинейность,
токи и шум не моделируются. Реальная АЦП ESP32 требует собственной настройки
и калибровки: формулы стенда нельзя переносить без проверки.

Источники API: [Espressif LEDC](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/ledc.html),
[Espressif GPIO](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/peripherals/gpio.html),
[JSCPP](https://github.com/felixhao28/JSCPP).

Внешняя цепь ограничена цифровой моделью: светодиод, резистор, кнопка,
учебный TMP36 и фрагмент макетной платы. Это не универсальный аналоговый симулятор.
Общей базы результатов учащихся и личных кабинетов пока нет.

Сторонние компоненты и уведомления перечислены в `dist/licenses.html`
и `dist/licenses/`. Сохраняйте эти файлы при размещении.
